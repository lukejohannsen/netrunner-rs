# Rules Conformance — the engine and the board against the Comprehensive Rules

**Checked against v26.03** (effective 02 March 2026). The copy is
[`rules/comprehensive-rules.md`](../../rules/comprehensive-rules.md), © Null
Signal Games ([NOTICE](../../rules/NOTICE.md)). When `rules/manifest.json`
names a later version than this line, every status below is stale until it
has been re-read against the rules that version changed.

The Rules Audit ([rules-audit.md](rules-audit.md)) was organised by the
engine's gaps, and it read the rules where a gap led it. This file is
organised by the rules, so the question "have we read section X against the
engine?" has one answer, in one place.

## How this is kept

- **`scripts/rules_sync.py` owns the copy.** It writes
  `rules/comprehensive-rules.md` (one line per rule, number and anchor first,
  so a grep lands on one rule) and `rules/manifest.json` (each rule's number
  and a hash of its text, keyed by the page's anchor, which does not change
  when rules are renumbered). Never edit either by hand.
- **`--check` is the watch.** `.github/workflows/rules-watch.yml` runs it
  every Monday and opens an issue when Null Signal Games' page differs. The
  report names the rules added, removed, changed or renumbered, and every
  `CR <number>` in the workspace that points at one of them.
- **Adopting a version is one PR:** run the script, fix what
  `rules_citations` names, re-read each changed rule against the engine,
  update the statuses below and the version line above.
- **Citations are checked.** `crates/netrunner_core/tests/rules_citations.rs`
  fails on any `CR <number>` or `Comprehensive Rules <number>` the committed
  copy does not contain. Its first run found one: Priority Construction's
  example was cited as 1.12.3a and is 1.12.2a.

**Statuses.** *conforms*: read rule by rule against the engine, and it
matches. *read in part*: some rules were read (the notes say which), and the
section as a whole has not been. *deviates*: a known difference, with the
fix owed. *not modelled*: no card in the pool needs it. *n/a*: nothing for
software to implement. *unreviewed*: not yet read. Adding a "Cited: …" note
to a row does not make it *conforms*; a row gets that status only after its
section has been read end to end.

## Findings

A reading of chapters 1–10 against `crates/netrunner_core` on 21 September 2026, filed as findings
A1–G2. The letters are this file's addresses ("Rules Conformance B1") and are permanent. Each finding's
record — the rule quoted, the fix, the measurement — is in
[`archive/rules-conformance.md`](archive/rules-conformance.md) under the same letter; here is one line each.

- **A1 fixed** — the Runner saw HQ and R&D cards before accessing them (7.3.4a, 7.4.7); access is one card at a time (`fix/access-one-at-a-time`).
- **A2 fixed** — Archives kept arrival order (4.4.2, "Discard piles are not ordered"); anyone but the Corp sees the pile faceup cards first, by name.
- **A3 fixed** — installing over a remote's root showed the old card's type (4.6.6f); closed with B.
- **B1 fixed** — a program over the memory limit was refused where the rules trash (3.9.3b, 8.5.6c); the Runner picks what goes, one card at a time.
- **B2 fixed** — a second console was refused (3.8.5b, 10.3.1d); the older one is trashed by the checkpoint.
- **B3 fixed** — the Corp's optional install trashes were never offered; `trash_first` is its own install entry.
- **B4 recorded, not built** — an install by a card's text makes only the forced trashes (8.5.6 applies to every install); no pool card installs over something on purpose.
- **C1 fixed** — the Corp drew before its turn began (5.6.1); the draw is inside the turn, after the turn-begins triggers (fixed again in TAI Stage 1).
- **C2 fixed** — end of turn is discard, window, clicks lost (5.6.3, 5.7.2).
- **C3 fixed** — the turn could be ended with clicks left (5.6.2b, 9.2.6b); `RulesError::ClicksRemain`, and the clients' "ask twice" went.
- **D1 fixed** — the Runner could pay to trash a card in Archives (7.1.5b).
- **D2 fixed** — the Corp could rez during access and after success (6.9, 7.2); `CompleteRun` declares the run successful and the windows are the rules' (`fix/run-and-access-windows`).
- **D3 fixed** — window permissions: a non-ice rez in the wrong window is refused (`paid_ability::window_permits_rez`).
- **D4 fixed** — the movement phase had no paid-ability window before the jack-out decision (6.9.4b) (`fix/jack-out-window`).
- **E1 fixed** — a card that made the Corp draw from an empty R&D did not end the game (1.7.2c); the Runner wins.
- **E2 fixed** — a maximum hand size below 0 did not flatline (1.7.2b); the hand size is signed.
- **E3 recorded, not built** — a simultaneous 7-point win is not a draw (1.7.1a); no card reaches it.
- **F1 fixed** — [click] abilities can be used inside paid-ability windows (9.5.2a, 9.2.7b) — deliberate and correct; the reading is recorded.
- **F2 fixed** — every `DamageTaken` counted as damage the Corp did (10.4.1); `DamageTaken::responsible` is the side whose card did it.
- **F3 fixed** — a forfeit did not lower `agenda_points` in the view.
- **F4 fixed** — Corp cards hosted on Detente went to the heap when it was trashed (1.19.1).
- **F5 fixed** — a "for each" that came to 0 still gained credits (9.12.2b); a gain of 0 emits nothing.
- **F6 one of three fixed** — Zwicky's "may" was forced (`fix/zwicky-may`); **recorded, not built:** an operation's reactions resolve after its play abilities (8.6.7), and the operation is filed in Archives before it resolves (partly mitigated in RWR Stage 1).
- **G1, G2 fixed** — the agenda-point range was one point too wide and three legality gaps (1.4) (`fix/deck-legality-matches-cr-1-4`).
