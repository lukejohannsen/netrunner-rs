## 1. Event Stream to Clients — DONE
`ServerMessage::ActionLog` carries one entry per action (since Phase 1.5). **Masked per viewer** (`fix/masked-action-log`): the raw entry had gone to both seats, naming unrezzed installs and access picks. `rules::masking::mask_action_for_player -> PublicAction { Visible | Concealed(ConcealedAction) }` — the six card-naming shapes keep their structure, because "the Corp installed into Remote 0" is information the Runner must have; `mask_event_for_player` drops an event whose information *is* a concealed identity and strikes the card out where it can, reading **conservatively from the post-action state**. `netrunner_session::PublicHistoryEntry` is reached only through `Session::last_entry_for(side)` — valid right after the action, no batch form, because masking an old entry against a later state reveals cards. The TUI pumps `step` one action at a time. Gate: `no_client_view_or_log_entry_ever_names_a_card_it_conceals`, widened to the opponent's hidden zones. **Closed 5 September 2026** (`feat/narrated-action-log`): `CardInstalled`, `CardAdvanced` and `IceSwapped` carry an `InstallId` and an `Option<CardId>`, so masking strikes the identity in place — the third, fourth and fifth fields that can be, after `TraceInitiated` and `PendingCardSelectionOffered` — instead of dropping the event. The handle is public (`PublicInstalledCard::install_id`), and for advancement so is the count, so the dropped event had been telling a viewer *less than their own board already showed them*. A swap is the case that needed it most: it comes from a card's text (Tāo Salonga, Brân 1.0) and no `PlayerAction` names it, so the event was the Runner's only possible record and there was none. `netrunner_cli` now narrates: `app::narrate_event` renders a line per event that says something the action line cannot, exhaustive over all 100 variants with 97 grouped as not-narrated, resolving every handle through the shared `app::install_label` against the viewer's own `ClientView` rather than trusting the event to name anything. A Runner reads "advanced the unrezzed card at Remote(0), now at 3 advancement tokens" where the log was previously silent. Gates: the fog sweep gained `assert_every_install_event_keeps_its_handle` (a real handle, not `InstallId::PLACEHOLDER` — the scan for leaked names cannot tell an event that says nothing from one that says which), and an `app.rs` test plays six real matches and checks each rendered line against what that seat concealed *at the moment it was written*. **Extended and closed 5 September 2026** (`feat/narrate-consequences`). The note above was wrong about half of what it deferred. `CardMoved` and `CardDerezzed` took handles on the same argument as the first three — a move keeps the card's install id and both servers are public, a derez is a rez state flipping on a public handle — and now strike rather than drop; they fire **42 and 19 times in 132 random-vs-random games**, so this was not a corner. **`CountersAdded`/`CountersRemoved` must not, and that is the durable finding**: `PublicInstalledCard::counters` is `None` on a face-down Corp card for its own stated reason, "whose counters would otherwise leak what it is (a *Nico Campaign* draining credits is recognisable long before it is rezzed)", so "the counters on install #7 changed" publishes exactly what the view withholds. They stay dropped, the reason is on the variants and on the masking arm, and `counters_on_a_facedown_install_stay_dropped_rather_than_struck` fails if anyone completes the pattern. Counters are the most common of the five by far (1,803 added, 1,118 removed in the same 132 games), which is why the leak would have mattered.

Narration widened from 3 events to 31 in the same pass, on a criterion stated once: narrate what no `PlayerAction` implies and a player would want logged — damage, tags, a trigger firing, a subroutine resolving, an agenda's point value, how a run ended, whether a trace landed — and stay silent on bookkeeping. Duplicates are suppressed in one `action_implies` helper (rez, remove-tag, click-break, install, jack-out) rather than per arm. **Measured over six matches: 73 narrated lines before, 519 after**, against 2,172 actions; over the 132-game report the narrated set covers 13,688 event occurrences. Narration needs no leak analysis of its own — it runs on an already-masked entry — but the UI is where a rendering mistake would show, so the end-to-end test became `no_rendered_log_line_names_a_card_the_seat_conceals`: **every** rendered line, checked against the board as it stood when that line was written, minus titles the view accounts for elsewhere (two copies of one ice, one rezzed, make the name printable) and minus what the seat's own action names (it accessed the card). The sweep's `assert_every_install_event_keeps_its_handle` now covers all five events.

## 2. Reconnection & Session Recovery — DONE
`feat/reconnect-handshake`: a per-seat `session_token` (v4 `Uuid`) in `MatchJoined`; `ClientMessage::Resume` answered with `MatchJoined` and a fresh `StateUpdate`, or `ResumeRejected`. The seat outlives its channel pair (`ChannelSeat.detached`, `ReattachHandle`; `await_seat` is a `select!` over the seat's rx, the reattach channel and the deadline); **newest connection wins**. **The grace clock (`DEFAULT_RECONNECT_GRACE` 30s) starts when the seat is needed**, resets on reattach, and expiry reports `GameEndReason::Disconnected` — a transport outcome, never from `classify_end_reason`. Tokens live in `serve` (`SeatTicket`), registered in `start_match`. The client's `Reconnector` makes one bounded attempt per render tick, 60s total — longer than the grace so a forfeited seat learns it from `ResumeRejected`. Dropped `ActionLog` entries are not replayed. Fixed in passing: a ping frame ended the stream.

## 3. Multi-Match Daemon & Matchmaking — DONE
- **Registry, lobby queue, rooms, cap, per-match seed** (`feat/match-registry`): one `Registry` under one `std` mutex — the operations that matter are compound (a pairing must sweep the lobby, check the cap, claim an index and register two tickets as one step). The lobby is a queue and **a waiter's token is the seat's token** (`Queued { session_token, position }`); ghosts are swept on every pairing and `ListMatches`; `ListMatches → MatchList` of `MatchSummary`; `--max-matches` refuses with `ConnectRejected` before queueing; `--seed` fixed (match `n` plays `seed + n`). `--room` in the CLI. Open: resuming a lobby place from the CLI; a graceful shutdown.
- **Turn timers** (`feat/turn-timers`): `--turn-timeout-secs`, **per decision**, cleared only when an action *applies* (a rejected action does not restart it), not reset by a reattach, and it **forfeits, never auto-plays** (`GameEndReason::TimedOut`). `DecisionClock { side, remaining }` once per decision; nothing is sent when the clock is off.
- **Spectators** (`feat/spectators`): `Spectate { match_id }` → `Spectating` plus every update, masked as `Viewer::Spectator` — **the intersection of what the two players see**. Every gate reads `viewer.is(owner)`, so there is no third code path; every masking entry point takes `impl Into<Viewer>`; `ClientView.side` became `viewer`. The fog gate checks the spectator against the union of both concealed sets. `SeatControl::{Reattach, AddSpectator}` on one control channel; spectators are drained sinks holding no token. CLI `matches`, `--spectate`. Open: spectator counts and caps; a delayed omniscient stream.
- **The daemon deals the published pool** (`feat/serve-plays-the-sample-pool`): every hosted match had been on the blank-padded Kate-vs-HB fixture (24 of 45 Corp cards did nothing), so every rating ever written was on that board. `sample_decks_for_seed(seed) = matchups()[seed % len]`; `--corp-deck`/`--runner-deck` pin a side at `bind`. Deleting the fixture deleted the `netrunner_cli::decks` mirror of it. Decklist ids are on the wire (`MatchJoined`, `MatchSummary`, `#[serde(default)]`). Open: `netrunner_single_player/tests/common/mod.rs` holds the last filler near-copy; the TUI header does not show the matchup.
- **A player brings their own deck** (`feat/online-from-the-menu`, Phase 6 §3, 13 September 2026): `Connect { deck: Option<Box<DeckFile>> }`, `serde(default)` and skipped when `None`, so an older client still connects and is dealt one. **The deck is the seat**: its side overrides a preference, a contradicting `preferred_side` is refused, and it is validated against the daemon's `--format` at the door (`check_brought_deck`, the same `DeckFile::validate` a pinned deck gets) — refused with `ConnectRejected` before it reaches the lobby or a bot. It replaces the deal for its side in `start_match`, pin or rotation; the operator's pin is the default for a seat nobody brought a deck to. **Pairing respects it**: `compatible` skips a waiter whose deck is for the same side, so two Corp decks both wait for a Runner rather than one being seated as the Runner (`two_decks_for_the_same_side_never_pair`). A daemon older than this ignores the field and deals, which the client detects by comparing `MatchJoined`'s deck id and says on the header. Also: the CLI sends the player's own name instead of `"CLI Player"`, `--deck` brings one on the flag path, and the client's writer closes the socket with a `Close` frame when its sender goes, so an abandoned lobby wait leaves the lobby instead of being paired as a ghost.

## 5. A rating is a server's to keep: identity is a key, a game leaves a signed receipt — DONE (8 October 2026)

`docs/server-tracked-rating`. **No code; the reasoning is `docs/identity-and-rating.md` and this entry is its index.** It follows `fix/local-play-is-casual` (Phase 3 §2, same day), which took the rating *out* of the client: a rating is a claim to someone else, so it means something only between people and only when somebody other than the rated player keeps it. What is left to decide is how a server keeps one, and the hole in what it does today.

**The daemon already rates human against human, under whatever name the client typed.** `Track::HumanVsHuman` and `Shared::rate` work and survive a restart (`tests/lobby.rs`), but the participant id is `Connect.player_name`, unverified (`PendingHuman::seated`). Anyone can be anyone. And the evidence is thrown away: `MatchRecordHeader` + the JSON-Lines `MatchHistory` replay bit-identically, and `MatchSession::run_with_outcome` drops the history it is handed.

**The decisions, each with what was rejected:**

- **Identity is an Ed25519 key the client holds; a name is a label.** Confirmed by the person on 26 September 2026: trust at login matters, and changing a name must change nothing, because the key is who someone is. The rating id is `key:<base32>`. The secret has its own 0600 file, never `settings.json` (the file people paste into bug reports). Rejected: accounts — a user table, a reset flow and a secret the *server* must protect, for a hobby server. A new pure crate `netrunner_identity` carries it; `netrunner_core` keeps its three dependencies, and `deny.toml` needs no edit (`ed25519-dalek` is BSD-3-Clause, already allowed).
- **Proved by a challenge that names the server.** `Identify` → `Challenge { nonce, server_key }` → `Prove`, signed over `"netrunner-auth-v1" ‖ server_key ‖ nonce`: the server's own key in the signed bytes is what stops a hostile server relaying an honest one's challenge to log in there as its visitor. An unidentified `Connect` still plays, unrated. The handshake protects the key, not the session: a public rating server sits behind TLS, as a deployment requirement and not daemon code.
- **Seat commitments and a server receipt, not a signature per action.** Each player signs once at `MatchJoined` (match, side, both keys, deck hash); the server signs the finished record's hash with the result and sends both players that receipt in a new `ServerMessage::Rated` — which is also Phase 3 §2's "not built: telling the remote client its new rating". Statements are signed as bytes, never as re-serialized JSON. Rejected *for now*: a per-action hash chain, which buys verification by someone who does not trust the server (federation, portable ratings) at a signature per `SubmitAction`; the record's footer reserves the field.
- **The results log is the truth and `ratings.json` is a cache.** Append-only receipts under `--data-dir`; folding them through `RatingBook::record` in order rebuilds the book exactly, so a corrupt book, a Glicko parameter change or voiding a cheater's games is a rebuild. Rejected for now: SQLite — nothing yet asks what a fold over a log cannot answer.
- **What is never rated:** any game with a bot in it (Phase 3 §2), and a game hosted in-process from the menu — the host's process holds the seed. Phase 6 §3's "Open: hosted games are unrated" closes as *by design*. Online, `Rewind::Free` is the only take-back a rated game offers; `Rewind::Undo` needs the other seat's consent — which is why the session's line and the engine's two classifiers were kept when local play stopped charging for it.
- **The trust boundary, stated:** a rating is a claim by one server's operator, who can see every seed. Keys are free, so a new key is provisional. Smurfing and win-trading are moderation, which the rebuildable log makes possible and cryptography does not solve.

**Stages, each its own branch and each useful without the next:** (a) the server keeps match records — no protocol change, and the server half of Phase 7 §8 item 15; (b) `netrunner_identity`, the client's key file, the handshake, ratings keyed by key; (c) seat commitments, receipts, `Rated`, `results.jsonl`, `--rebuild-ratings`; (d) client surfaces — the game-over panel and "your standing at `<server>`" on Profile, fetched and never stored as truth; (e) the free take-back online.

- **Left for later** (as written when (a)–(d) were built): stage (e), the free take-back online — built 8 October 2026, below. Rotating a key (the old one signing the new) is still recorded and not designed. Stage (d) will show the player their key, with "losing this file loses you; copying it plays as you elsewhere" beside it.

**Settled by §6 item 2 (25 September 2026):** the messages live in `netrunner_protocol`, which `netrunner_client` depends on without the server. **Open:** Key rotation (a successor statement signed by the old key) is recorded and not designed.

**Stage (b), the server half** (`feat/key-identity-server`, 26 September 2026). Built before stage (a), because §7's public server wants the key more than it wants the records, and neither needs the other.
- **`netrunner_identity`**, a new pure crate: `Identity` (the secret, `Debug` printing only the public half), `PublicKey` (52 characters of lower-case base32, `key:<base32>` as a rating id, a 14-character fingerprint), `Nonce`, `Signature`, and the login statement `auth_statement` = `"netrunner-auth-v1" ‖ server key ‖ nonce`, checked with strict verification. No RNG of its own: a key is made from 32 bytes the caller drew, so the crate's dependencies are `ed25519-dalek` 3 (the version iroh already links), `data-encoding`, `serde` and `thiserror`, and `deny.toml` is unchanged.
- **The messages:** `Identify { key }` → `Challenge { nonce, server_key, lasting }` → `Prove { signature }` → `Identified { key }` or `IdentifyRefused`, answered in the handshake loop before `Attach` or `Resume`. A refused proof closes the socket, because a client that meant to be rated should learn at once. `lasting` is new since the design: a daemon with no data directory makes a new key each run, and a client that pinned it would only ever cry wolf.
- **`--data-dir` replaces `--ratings-file`**, holding `identity.key` (created 0600, never replaced when unreadable — that is a bind error), `players.json` and `ratings.json`. `players.json` is a map rewritten whole rather than the sketched `players.jsonl`, because last-seen changes on every visit.
- **Rated:** two proved keys, and two different ones. One key in both chairs goes unrated, since it would farm one role's rating off the other's. An unidentified seat plays unrated, and a bot game's human seat now carries no rating id at all.
- Tests (`tests/identity.rs`): an honest proof, and a challenge naming the server's key; a fresh nonce per connection; a wrong key's signature, a proof made for another server (the relay) and a proof with no challenge each refused and closed; the key kept across a restart at 0600 and an unreadable one refusing to bind; a rating that follows the key through a rename and a restart, with nothing filed under a name; an unidentified seat and a key playing itself, both unrated.
- **The client half** (`feat/key-identity-client`, same day).
  - `netrunner_client::identity` owns the files: `identity.key` beside the settings, made on first use at 0600 and never replaced when unreadable, and `known_servers.json`, the servers' keys by the address they were dialled at. Both sit under `$NETRUNNER_IDENTITY_DIR` when it is set.
  - `connection::Seat` carries optional `Credentials`. The machine proves the key on every transport it opens, a reconnect included, before `Attach` or `Resume`. A spectator never identifies.
  - A lasting server key is held to the one remembered for the address (`with_pinned`). A key met for the first time is reported (`Event::ServerKey`) and written by the driver. A different key ends the connection with `ConnectionError::ServerKeyChanged`, naming both fingerprints and the file to edit, before anything is proved to it.
  - Only an address is pinned. A ticket already names its host's key, and a hosted game is never rated, so neither client proves a key to a game it hosts.
  - Both clients' Join prove the key: the desktop through `ClientCore::credentials`, and the terminal's menu and `--server` path through the same module. The flag path plays unrated with a warning when there is no data directory. An unreadable key file stops the join with the error, rather than playing a game that quietly counts for nothing.
  - `PublicKey` is now held as its 32 checked bytes, because the decompressed point made every message and error holding one about 200 bytes larger. The credentials are boxed on a `Seat` for the same reason.
  - Tests: six machine tests (proving before attaching and learning a lasting key; a passing key neither remembered nor checked; a changed key refused before any proof; a refused proof; a reconnect proving again then resuming, held to the key met first; a spectator proving nothing). One driver test against a real server with a data directory: the key remembered by address, then a different remembered key refused. Three for the files: made once at 0600, an unreadable file left alone, a server found by its address. The desktop's and the terminal's join tests now identify through a test directory.
**Stage (a): the server keeps match records** (`feat/server-keeps-match-records`, 26 September 2026).
- `MatchSession::run_with_outcome` returns a `Finished { state, history, outcome }`. It used to drop the history.
- `start_match` builds the `MatchRecordHeader` from the exact inputs it gives `GameState::setup`: seed, both decks whole, default rules, a shuffled order, and the rung when a ladder bot sat.
- A daemon with a `--data-dir` writes `matches/<yyyy-mm>/<match id>.jsonl` when the match ends. Every match is written, a bot's and a stall included, because a record is evidence for a dispute or a bug report as much as for a rating. The month comes from a `civil_from_days` of a dozen lines rather than a calendar crate.
- **Written at the end, not appended as it goes:** a crash loses that match, and its seats with it. Appending would buy the prefix of an unfinished game at a write per action.
- Tests: the record's header names the brought deck whole and the seed; every recorded action applies again from `header.setup`; the month directory is right at a year's last second and on a leap day.
**Stage (c): seat commitments, receipts, `Rated`, the results log** (`feat/signed-receipts`, 26 September 2026).
- **Signed statements** (`netrunner_identity::Signed`): the key, the exact payload text and a signature over `tag ‖ '\n' ‖ payload`. A reader verifies the bytes before parsing them, so there is no canonical form to get wrong. `sha256_hex` names what a statement does not carry.
- **Seat commitment** (`netrunner_protocol::statements::SeatStatement`, tag `netrunner-seat-v1`). After `MatchJoined`, each proved seat gets `SignSeat { statement, salt }` naming the match, server key, side, both keys, a deck hash and the start time. The client machine signs it unasked and unshown, but only when the statement names its own key, the server that challenged it, the match and side it was seated in, and the hash of the deck it brought for that side. It answers `SeatSigned`, which the server keeps if it verifies.
  - **The deck hash is salted, and the salt is told to that seat alone.** A receipt carries both commitments to both players, and an unsalted hash of a well-known list would confirm a guess — leaking what §7 keeps private.
  - **Withholding the signature is not a way out of a loss.** A game is rated on the proved keys; a missing commitment only leaves the receipt without it.
- **Receipt** (`statements::Receipt`, tag `netrunner-receipt-v1`, signed by the server). It names both seats (name, key, commitment), the winner and reason, whether it is rated, the server's build, a card-pool hash (every definition's JSON in card order), the record file's SHA-256, the start and end times, and `action_chain: None`, reserved.
  - **Kept beside the record** as `<match id>.receipt.json`, not as a footer line: the record stays exactly what replay reads, and the hash is of exactly that file.
  - Signed for every match; only a rated one reaches the log and `Rated`.
- **`ServerMessage::Rated { receipt, before, after }`** goes to each seat of a rated game after `GameEnded`, with that seat's side's rating before and after. It is sent to the seat's *current* connection: `SeatTicket::tx` is replaced on resume. Phase 3 §2's "not built: telling the remote client its new rating" closes here.
- **`results.jsonl` is the truth, `ratings.json` a cache.** The receipt is appended under the same lock as the book is folded, so the log's order is the fold's. `--rebuild-ratings` (serve mode, needs `--data-dir`) refolds it before serving and checks every receipt against the daemon's key. A line nobody signed stops the rebuild and names its line.
- Tests (`tests/identity.rs`):
  - a rated game's receipt: signed by the server and no other key, both commitments verifying, the record's hash matching the kept file, the same receipt beside it and in the log, and ratings before and after for each side;
  - a withheld signature: still rated, with the commitment missing;
  - the book rebuilt byte for byte after two games, and a forged line refused.
  - Machine tests: a statement true to the seat is signed; another deck, side or salt is not.
**Stage (d): what the clients show** (`feat/rated-client-surfaces`, 26 September 2026).
- **The end of a rated game says what it did.** `play::MatchMessage::Rated { before, after }` follows `Ended`. The desktop's end panel and the terminal's end banner draw `identity::rated_line`: "Rated as the Corp at this server: 1500 → 1662 ± 290". The numbers are the server's; the client keeps none (Phase 3 §2).
- **The player keeps their receipts.** The connection driver appends every `Rated` receipt to `receipts.jsonl` beside the key, so a player can show their history even if a server loses its own.
- **Who the player is, and where they stand.**
  - The desktop's Profile shows the key's fingerprint, where it is kept, and the two facts about the file: lose it and you start again everywhere; copy it to play as you elsewhere (`identity::key_lines`).
  - Profile then shows the standing at every server remembered in `known_servers.json`. Those are the servers that keep their key, which are the ones that rate. Each standing is fetched on entering the screen, drawn as it arrives, and never stored.
  - The fetch is `remote::standing`: its own socket, proving the key, held to the remembered server key like a game is, answered by the new `ClientMessage::MyStanding` / `ServerMessage::Standing`.
- **The terminal:** `netrunner_cli record` and the Record screen add the key's lines. They read the key and never make one, because opening a screen writes nothing (`identity::key_lines_in`). `netrunner_cli standing` prints the key and the standing at `--server`.
- Tests:
  - the server reports a proved key's standing after a rated game, and none for a connection with no key;
  - the client's standing fetch finds nothing for a new key, remembers the server, and refuses a changed key;
  - the feed passes `Rated` on after the end;
  - the rated and standing lines.

**Stage (e): the free take-back online** (`feat/take-back-online`, 8 October 2026).
- **One request, and the host's two words.** `ClientMessage::TakeBack` asks for this seat's last move back. The host answers every seat and spectator with a fresh `StateUpdate` and then `TakenBack { by, removed, kind }` — as an applied action is its view and then its `ActionLog` — so each log drops the same `removed` entries. `ServerMessage::Back { rewind }` tells a seat what its take-back would do, sent only when it changes: a local match's `MatchMessage::Back`, on the wire. `netrunner_session::Rewind` is serialized for it.
- **The free kind anywhere, the undo where the lobby does not rate.** `MatchSession` keeps every channel seat's last moves (`Session::with_undo(UNDO_DEPTH)`, which the server never used to pay for), offers `Rewind::Free` in every match and `Rewind::Undo` only under `with_undo(true)`, which `start_match` sets from the lobby's `rated` — so a bot's lobby and a casual one take an undo at one press as a local game does, and a rated lobby refuses it with the reason: it would need the other seat's consent, which nothing asks for yet. The line kept by AGENTS.md's Session Rule is finally used for what it was kept for.
- **A seat takes back only its own move.** `Session::can_rewind_by` / `rewind_by`: the newest kept state is whichever seat moved last, and the other seat asking is refused — not handed the next state down, which the newer move has built on. The idle seat's request is read as its surrender is (`SeatEvent::IdleTakeBack`), because in an unrated game the Runner may undo the run the Corp is deciding a rez on. A reattached seat is told the standing offer with its fresh view.
- **Both clients through what they had.** `MatchHandle::rewind` sends the request at a host, and the feed turns `Back` and `TakenBack` into the `Back` and `Rewound` a local match sends, so the desktop's Take it back control works unchanged; `Rewound` now says `by` whom, and the log line reads "The Corp took that back." when it was the other seat's move. The terminal's remote `App` reads the offer, sends the request on `u`, pops its log and names the key in its hint line.
- Tests: the session's (only the seat that moved takes its move back); the match session's (a free take-back in a rated match puts both boards back and the other seat is refused; an undo refused in a rated match and taken in an unrated one, with the offer saying which); the sockets' (a casual lobby's undo, taken through the attached connection and seen by both seats); the feed's; the terminal app's (`u` after the offer, the log popped in whose name); the desktop model's (the other seat's take-back named); the remote handle's (a take-back at a real host).
- **Left open:** an undo in a rated game asked of the other seat (a consent exchange), and key rotation (the old key signing the new), recorded and not designed.

## 6. A host reachable from outside — DONE (25 September 2026)

Asked for as: a person hosts on their home network and friends outside it join, with no firewall rules. Three items, in order, each its own branch.

**What stood in the way.** Host a game bound `0.0.0.0` or `127.0.0.1`, IPv4 only. The address it shared came from an IPv4-only routing trick. `netrunner_server --host ::` built `::::8080`, which does not parse. `normalize_address` read the last group of a bare IPv6 address as a port. Nothing asked the router to open anything. The server itself was never the obstacle: it is a plain WebSocket listener and has served the whole of §1–§3 over one.

1. **IPv6, one dual-stack socket, and the router asked to open the port** (`feat/host-reachable-from-outside`, built):
   - `netrunner_client::hosting` binds `[::]` with `IPV6_V6ONLY` explicitly off, falling back to `0.0.0.0`. The option is set explicitly because Windows defaults it on.
   - It lists the addresses to give out, each with who can use them: the LAN IPv4, then a global-unicast IPv6.
   - For a third choice, "anyone on the internet", it asks the router for a TCP mapping over UPnP-IGD, NAT-PMP and PCP (`portmapper`, n0's).
   - The server gains `Server::from_listener` and no dependency; the daemon's `--host` brackets an IPv6 address.
   - **A mapping is reported as reachable only on a public address:** one on `100.64.0.0/10` or a private range is the router behind the provider's NAT.
   - **Every failure names the manual forward and Tailscale.** The forward is left out when the provider's NAT makes it useless.
   - `portmapper` added 47 crates to the workspace lock, all under licences `deny.toml` already allows. The alternative was `igd-next` with `crab_nat`: two crates for three protocols, and renewal to write.
   - Not tested against a router here: the TUI's handling of every answer is tested through a fake `PortMapper`. The real round trip is the manual check in the PR.
2. **A sans-IO client connection in `netrunner_client`** (`feat/sans-io-client-connection`, built). The pattern is Firezone's ([sans-IO](https://www.firezone.dev/blog/sans-io)).
   - **`connection::Connection` is told what happened**: a transport opened, a message arrived, the transport went away, the clock passed the deadline it named, the player sent something or left. **It says what to do**: dial, send these, tell the screen this, wake me at this instant. Time is an argument and never read.
   - **The rules of a connection it holds**:
     - the handshake;
     - the lobby;
     - a seat resumed by its token;
     - a place in the lobby resumed by the token `Queued` already carried (§3's "Open: resuming a lobby place" closes);
     - a spectator watching again;
     - no retry for a first connection that never got an answer, nor for a match that has ended;
     - an attempt every second, each bounded at 3 s, giving up after 60 s;
     - a first dial bounded at 10 s, where the old client had no bound at all.
   - **Tested without a socket or a clock**: eleven tests in 0.00 s, including the whole 60-second give-up, which the blocking `Reconnector` could only have been tested at the speed of real time.
   - **`remote` is the one driver**: a tokio task that dials, sends, reads and sleeps as the machine says, reporting through channels a caller only `try_recv`s. **A resume happens under the channel pair**: the same `rx` carries on, and a `watch` of the `Link` says what happened. So the terminal's `App` follows the link instead of swapping channels, its render loop no longer reconnects anything, and nothing on the render tick blocks.
   - The driver is tested against a real server through a proxy that can be cut: a cut socket mid-match is resumed and the next view arrives on the same `rx`.
   - **Messages, not bytes.** The machine takes typed messages rather than frames, because every transport this project has or plans carries whole messages. Bytes would put `serde_json` into every machine test for nothing.
   - **`netrunner_protocol`** is the wire messages lifted out of the server, which re-exports them, so `netrunner_client` names them without the server. That settles §5's open question.
   - **Not done: the server's side.** Its handshake stays tokio tasks, because its tests already drive it over sockets and nothing else needs to drive it.
3. **A peer-to-peer transport: join by ticket, not by address** (`feat/peer-to-peer-tickets`, built). Hosting for "anyone on the internet" now also gives out a ticket, which a joiner pastes where they would type an address.
   - **`netrunner_client::peer`, over iroh 1.2** (n0's; QUIC with hole punching, and a relay where punching fails). This is what reaches a host behind carrier-grade NAT with nothing installed, and it encrypts what the WebSocket sends in the clear.
   - **The WebSocket rides inside the QUIC stream.** The joiner opens one stream and speaks the same WebSocket the TCP server speaks. So the server's handshake, lobby and resume run unchanged, and the joiner's driver is `remote`'s with a different dial. The server gains `Server::acceptor()`, an `Acceptor` that serves any byte stream, and no dependency. Rejected: our own framing over the raw stream, which would be a second implementation of the handshake to keep in step with the first.
   - **The ticket is iroh's `EndpointTicket`** (`endpoint…`, base32): the host's key, its direct addresses and its relay. `remote::spawn`, `list_matches` and `normalize_address` tell a ticket from an address by parsing it, so every place that takes an address takes a ticket, `--server` included.
   - **"The relays are a service somebody runs": n0 runs them, unless the host names their own.** n0's public relays are free, in four regions, and see only encrypted QUIC between two keys. The host can name a relay of their own (`iroh-relay`) or none in `Settings::relay` (shared, since either client can host). **A joiner uses the relay the ticket names**, so only the host ever chooses. Rejected: n0's DNS address lookup (pkarr), which would let the ticket be the bare key. That is a second service to depend on, to shorten a string that is pasted rather than typed; the endpoint is built on `presets::Minimal`, not `N0`.
   - **A fresh key per hosted game.** A ticket lasts as long as the hosting. A lasting key is §5's player identity, which is Ed25519 as iroh's is, and can be handed to the endpoint when §5 builds the key file.
   - **Dropping a stream ends it politely:** the send half is finished and the connection closed once the other end has everything, or after five seconds. Closing a QUIC connection at once throws away what is in flight, and the last message is often the one that matters (a refusal, the end of the match).
   - **Tested:** a seat plays by ticket through the driver, `ListMatches` answers by ticket, and a ticket whose host has gone fails the first dial. The terminal's host gives a ticket and a joiner who pastes it is seated. All run with the relay off, so the ticket names this machine's own addresses and CI touches no network. **The relay by hand:** `cargo test -p netrunner_client -- --ignored public_relay` plays through n0's public relay with the direct addresses struck out of the ticket, so the relay is the only path; it passed on 25 September 2026.
   - **Cost:** iroh added 84 crates to the lock. `deny.toml` gains one licence, Unlicense, for three wasm-only crates under iroh's relay client.
   - **Not done:** the terminal's settings form does not edit `relay`; the file does. *The desktop's online screen, listed here as not done, is built (Phase 7 §7, 25 September 2026): it offers the ticket through `peer` and `remote` as the terminal does, and a resumed seat's `MatchJoined` is now passed on by the connection so a reader knows the fresh view that follows has no action behind it.* A resume after a dropped QUIC connection is the driver's ordinary resume and is tested only over TCP.

**Rejected, with the reasons:**
- **STUN alone.** It tells a machine its public address and nothing more. Hole punching also needs somewhere for the two sides to swap addresses, and a TURN relay for the NATs that defeat it (symmetric, carrier-grade). It is dependable only over UDP, while the game runs over TCP. That is item 3's shape, not a step on its own.
- **Raw WireGuard built into the app.** It is a tunnel, and someone must still be reachable and keys still exchanged: that is rebuilding Tailscale.
- **Tailscale or ZeroTier used as they are** need no code and work through every NAT, so they are the documented fallback (`docs/playing-online.md`), not a feature.

## 8. Four formats, and casual is a mode — DONE (11 October 2026)

The person's notes of 11 October 2026 ([`docs/online-play-design-2026-10-11.md`](../online-play-design-2026-10-11.md)) begin: "Change Deck type legality to just be STANDARD, STARTUP, SNAPSHOT, ETERNAL - no CASUAL (casual will be mode of play but still use legality)."

**Casual is not a Null Signal Games format.** `NsgFormat::Casual` is this project's own variant — every card the catalog knows, no ban list, no restriction list (`crates/netrunner_core/src/format.rs`) — and it became the default everywhere a person had not chosen a format: `settings::DEFAULT_FORMAT`, the terminal's and the daemon's `--format`, every bot's `Knowledge::default()` (the pool it samples the opponent's hidden cards from), `DeckCategory::format()` for every deck but the Sweep decks, the daemon's `DEFAULT_FORMATS` and so a permanent lobby whose id is `casual`. **Decided (11 October 2026):** `NsgFormat { Standard, Startup, Snapshot, Eternal }` — exactly what NetrunnerDB publishes — and `Casual` deleted with every default that leaned on it. Rejected: keeping `Casual` as an "any card" sandbox format behind another name — a deck legal in no published format is a deck the builder should refuse, and the sandbox was never asked for.

## 10. The server keeps a profile: a database behind the daemon — DONE (11 October 2026)

From the notes: "Servers need to hold data. Public Key and rank and any other server side data to be tracked … link up public-key to achievements, name, and other things for the game. Game DB backend should be a zero touch easy setup of SQLite but also be able to use a PostGres setup if a server actually becomes popular."

Today the daemon keeps six JSON files under `--data-dir`, each rewritten whole under the registry's mutex from inside tokio tasks (`identity.key`, `players.json`, `ratings.json`, `results.jsonl`, `tournaments.json`, `matches/`); `players.json` is a write-only name label that nothing reads back; there is no ladder message and no profile. `docs/identity-and-rating.md` §4 rejected SQLite "for now … It becomes the right move when a ladder page or a match search does." §9's ladder per format, the profile and the pairing memory are that page.

**Decided (11 October 2026):**
- **A crate of its own, `netrunner_store`**, so the desktop — which depends on the server crate to host a game in-process — compiles no database it does not use: the in-process host runs with no store (`Store::None`), unrated and profile-less as it is today. The store is `sqlx` with the `sqlite` and `postgres` features behind one API: a daemon with `--data-dir` and nothing else opens an SQLite file there and needs no setup; `--database postgres://…` is the popular server's. Rejected: two hand-written backends behind a trait (twice the queries), and a single-file database read whole into memory (it is what the JSON files are now, and it is what a ladder cannot be built on).
- **The results log stays the signed truth; the store is the index.** `results.jsonl` and the receipts are what anyone can recompute a rating from; the store holds what a question needs answered quickly: players (key, name, first and last seen, the active title and badge), the rating per format, the results, the titles and badges earned (which, when, by which event — §11), `last_pairing` (§9), tournaments and events. `--rebuild-ratings` becomes a rebuild of the store from the log.
- **The profile is the player's to read and, in part, to set.** `MyProfile` answers over the attached connection — name, the rating per format, the titles and badges earned, the active ones; `SetProfile { title, badge }` chooses among those earned, never grants one; `Ladder { format }` is the page `identity-and-rating.md` §5 reserved, listing a key only after some number of games.
- The organizer's and the operator's data (§12) live in the same store.

**Staging:** the crate with SQLite alone and the players and ratings tables, the daemon reading and writing it where the JSON files were (the log kept); the profile messages and the clients' profile and connections manager (Phase 7 §14); Postgres last, behind the same tests.

**Built, stage 1 (11 October 2026, `feat/store-sqlite`).**
- **`netrunner_store`**: engine-free and rating-free — keys, formats and roles cross it as the strings the workspace prints — over `sqlx::Any`, with the drivers as features (`sqlite`, `postgres`) so the clients, which depend on the server crate to host in-process, build none (`default-features = false` on their side; the daemon binary turns `sqlite` on). The dialect is what both databases read: `CREATE TABLE IF NOT EXISTS`, `ON CONFLICT … DO UPDATE`, `TEXT` / `BIGINT` / `DOUBLE PRECISION`, and `$1` placeholders each used once in order, because SQLite takes `$1` as a *name* and sqlx binds by position. No migrations: nothing is released, so the schema is made on open and `SCHEMA_VERSION` written for the day one is needed. Tables: `players` (key, name, first and last seen, the title and badge worn), `ratings` (key, format, role, the Glicko-2 numbers and the tally), `results` (the index of the log, each with its receipt's line), `awards` (title or badge, when, by what — empty until §11 and §12 grant), `last_pairing` (which chairs two keys last took, written at every game between two keys, rated or not, so §9 finds the memory there), `tournaments` (the document as JSON, one row each — the Swiss state is a document nothing queries inside).
- **The daemon on it** (`serve::store`): `--data-dir` alone opens `store.sqlite` there, `--database <url>` opens that instead; `players.json`, `ratings.json` and `tournaments.json` are gone, each of which was rewritten whole on every change. **One writer, in order**: a change is decided under the registry's lock — the book folded with the log append, the tournament changed — and the rows that record it are queued to one task that lands them in that order, so two games ending at once never leave an older standing over a newer one; **a game's rows land in one transaction** (`Store::record_game`), because CI's first run read a ladder between one player's row and the other's and saw half a game; the book stays in memory as the working copy, loaded from the rows at bind. `--rebuild-ratings` became `--rebuild`: the ratings and results emptied and folded again from the log, the rest kept. `Server::from_listener`, which both clients host in-process through, refuses a data directory, since opening a store is an await and a hosted game is never rated.
- **A ladder per format** (§9's decision, built here): `Track::Ladder(Format)` replaces `HumanVsHuman`, spelled `ladder:standard` as a map key and a store column; `Receipt::format` names the ladder a game counts toward, so the log alone rebuilds every ladder; `ServerMessage::Standing { key, standings }` lists a `FormatStanding` per ladder the key has played on, in the formats' order, and both clients' line over Find a game reads the lobby's format's standing alone ("Rated here. In Standard: As Corp: 1612 ± 120 (3–1–0)" or "No rated games in Startup yet"), the Profile screen and `netrunner_cli standing` every format's.
- Tests: the store's own on a scratch SQLite file (a player seen twice, a rating row replaced by its key, format and role; results, awards, pairings and tournaments round-tripping; the file reopening at its version); the writer's rows-to-book round trip; the daemon's over real sockets, now reading the store — a rating follows the key on the Startup ladder alone, the names and the pairing in the players and pairing tables, a bot's and an unidentified seat's games leaving no row, the store emptied and rebuilt row for row from the log, a tournament outliving the daemon through the store; the clients' standing words per format.
- **Left for stage 3**: the `postgres` feature's tests against a live server, and a service job in the weekly workflow (built, below).

**Built, stage 2 (11 October 2026, `feat/profile-messages`).**
