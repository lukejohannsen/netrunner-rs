# Phase 4 — Network Resilience & Server Infrastructure

Area roadmap; the index is `ROADMAP.md`. Addresses: "Phase 4 §1"–"§4". The server sends **full masked `ClientView` snapshots** after every action, not deltas — the current design, not an oversight (§4).

## 1. Event Stream to Clients — DONE
`ServerMessage::ActionLog` carries one entry per action (since Phase 1.5). **Masked per viewer** (`fix/masked-action-log`): the raw entry had gone to both seats, naming unrezzed installs and access picks. `rules::masking::mask_action_for_player -> PublicAction { Visible | Concealed(ConcealedAction) }` — the six card-naming shapes keep their structure, because "the Corp installed into Remote 0" is information the Runner must have; `mask_event_for_player` drops an event whose information *is* a concealed identity and strikes the card out where it can, reading **conservatively from the post-action state**. `netrunner_session::PublicHistoryEntry` is reached only through `Session::last_entry_for(side)` — valid right after the action, no batch form, because masking an old entry against a later state reveals cards. The TUI pumps `step` one action at a time. Gate: `no_client_view_or_log_entry_ever_names_a_card_it_conceals`, widened to the opponent's hidden zones. **Closed 5 September 2026** (`feat/narrated-action-log`): `CardInstalled`, `CardAdvanced` and `IceSwapped` carry an `InstallId` and an `Option<CardId>`, so masking strikes the identity in place — the third, fourth and fifth fields that can be, after `TraceInitiated` and `PendingCardSelectionOffered` — instead of dropping the event. The handle is public (`PublicInstalledCard::install_id`), and for advancement so is the count, so the dropped event had been telling a viewer *less than their own board already showed them*. A swap is the case that needed it most: it comes from a card's text (Tāo Salonga, Brân 1.0) and no `PlayerAction` names it, so the event was the Runner's only possible record and there was none. `netrunner_cli` now narrates: `app::narrate_event` renders a line per event that says something the action line cannot, exhaustive over all 100 variants with 97 grouped as not-narrated, resolving every handle through the shared `app::install_label` against the viewer's own `ClientView` rather than trusting the event to name anything. A Runner reads "advanced the unrezzed card at Remote(0), now at 3 advancement tokens" where the log was previously silent. Gates: the fog sweep gained `assert_every_install_event_keeps_its_handle` (a real handle, not `InstallId::PLACEHOLDER` — the scan for leaked names cannot tell an event that says nothing from one that says which), and an `app.rs` test plays six real matches and checks each rendered line against what that seat concealed *at the moment it was written*. Still open on the same argument: `CountersAdded`, `CountersRemoved`, `CardMoved` and `CardDerezzed` carry no handle and are still dropped whole.

## 2. Reconnection & Session Recovery — DONE
`feat/reconnect-handshake`: a per-seat `session_token` (v4 `Uuid`) in `MatchJoined`; `ClientMessage::Resume` answered with `MatchJoined` and a fresh `StateUpdate`, or `ResumeRejected`. The seat outlives its channel pair (`ChannelSeat.detached`, `ReattachHandle`; `await_seat` is a `select!` over the seat's rx, the reattach channel and the deadline); **newest connection wins**. **The grace clock (`DEFAULT_RECONNECT_GRACE` 30s) starts when the seat is needed**, resets on reattach, and expiry reports `GameEndReason::Disconnected` — a transport outcome, never from `classify_end_reason`. Tokens live in `serve` (`SeatTicket`), registered in `start_match`. The client's `Reconnector` makes one bounded attempt per render tick, 60s total — longer than the grace so a forfeited seat learns it from `ResumeRejected`. Dropped `ActionLog` entries are not replayed. Fixed in passing: a ping frame ended the stream.

## 3. Multi-Match Daemon & Matchmaking — DONE
- **Registry, lobby queue, rooms, cap, per-match seed** (`feat/match-registry`): one `Registry` under one `std` mutex — the operations that matter are compound (a pairing must sweep the lobby, check the cap, claim an index and register two tickets as one step). The lobby is a queue and **a waiter's token is the seat's token** (`Queued { session_token, position }`); ghosts are swept on every pairing and `ListMatches`; `ListMatches → MatchList` of `MatchSummary`; `--max-matches` refuses with `ConnectRejected` before queueing; `--seed` fixed (match `n` plays `seed + n`). `--room` in the CLI. Open: resuming a lobby place from the CLI; a graceful shutdown.
- **Turn timers** (`feat/turn-timers`): `--turn-timeout-secs`, **per decision**, cleared only when an action *applies* (a rejected action does not restart it), not reset by a reattach, and it **forfeits, never auto-plays** (`GameEndReason::TimedOut`). `DecisionClock { side, remaining }` once per decision; nothing is sent when the clock is off.
- **Spectators** (`feat/spectators`): `Spectate { match_id }` → `Spectating` plus every update, masked as `Viewer::Spectator` — **the intersection of what the two players see**. Every gate reads `viewer.is(owner)`, so there is no third code path; every masking entry point takes `impl Into<Viewer>`; `ClientView.side` became `viewer`. The fog gate checks the spectator against the union of both concealed sets. `SeatControl::{Reattach, AddSpectator}` on one control channel; spectators are drained sinks holding no token. CLI `matches`, `--spectate`. Open: spectator counts and caps; a delayed omniscient stream.
- **The daemon deals the published pool** (`feat/serve-plays-the-sample-pool`): every hosted match had been on the blank-padded Kate-vs-HB fixture (24 of 45 Corp cards did nothing), so every rating ever written was on that board. `sample_decks_for_seed(seed) = matchups()[seed % len]`; `--corp-deck`/`--runner-deck` pin a side at `bind`. Deleting the fixture deleted the `netrunner_cli::decks` mirror of it. Decklist ids are on the wire (`MatchJoined`, `MatchSummary`, `#[serde(default)]`). Open: `netrunner_single_player/tests/common/mod.rs` holds the last filler near-copy; the TUI header does not show the matchup.
