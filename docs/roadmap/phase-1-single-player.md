# Phase 1 — Single-Player Completeness (and Phase 1.5, Session Unification)

Area roadmap; the index is `ROADMAP.md`. Section numbers are addresses used by code comments ("ROADMAP Phase 1 §3", "Phase 1 §8 Stage 5") and never change.

## 1. Saved Decks End-to-End — DONE

Scoped as *deck import*, shipped as a **saved deck format**: deckbuilding happens against the cards the engine implements, never by parsing a user's NetrunnerDB JSON. `deck::Decklist`/`deck::validator` are reached by converting a saved deck into their numeric-keyed shape.

- `decks::DeckFile` is the one authored format; the published NSG decks became ordinary decks that ship embedded. `netrunner_core` does no I/O (`from_json`/`to_json`); the CLI's `deck_store` owns directories, written temp-file-plus-rename.
- **`DeckCategory` defaults to `Custom`, and `decks::matchups()` filters to `Sample`**: a deck that forgets its category is excluded from training rather than silently added. (Landed Phase 1.75 §3's `kind` field early.)
- The three deck types and two validators are reconciled, not merged; `DeckFile::validate` runs both, executability first. The deckbuilding validator had never run on anything before this — it now checks every published deck, which spend 14–15 of 15 influence.
- CLI: `--corp-deck`/`--runner-deck` resolve built-in id → saved name → path and fail hard at play time on either validator. `deck list|show|validate|new|add|remove`; an illegal deck under construction is a note, not a rejection. Decks live in `dirs::data_dir()/netrunner/decks` (`--decks-dir`, `NETRUNNER_DECKS_DIR`).
- **Gotcha:** `netrunner_cli` has no `lib.rs`; `tests/onnx_opponent.rs` reaches source via `#[path]` and is the crate root for that binary — declare every module a path-included module reaches.

- **Dynamic discard re-check**: `turn::cards_over_hand_limit` re-derives from live hand size; the stored `required` is a report. Defensive — no `CardDiscarded` dispatch arm exists yet.

## 5. Format Support — mechanisms DONE, data deliberately a seed (5 September 2026)

`feat/format-support`. The four sub-items resolve differently, and separating them is the point.

- **Points — done, and it replaced a rule the code knew was wrong.** `FormatRules::restricted` was a `HashSet` of cards each capped to one copy, with a doc comment admitting it approximated a rule it could not express: the real restriction constrains the *deck*, not the card. It is now a budget — `restriction_points` per card, `restriction_budget` per deck — of which "at most one restricted card" is the special case of cost 1 and budget 1. Cost counts once per distinct card, not per copy, so three copies of one listed card is legal and one copy each of two is not, which is exactly the distinction the old cap got backwards. New `RestrictionBudgetExceeded`. `Default` is hand-written because the budget must default to unlimited, where `u32::default()` would make any listed card instantly illegal. **Behaviour-neutral on shipped data** (every list is empty), which is how a mechanism change should land: 927 core tests unchanged.
- **Legality before match start — done, on the side that was missing it.** The client path already validated everywhere: `--format` is global and reaches `deck show`, `deck validate`, the TUI and headless through `decks_for_match`. **The daemon validated nothing.** `pin_deck` checked a deck's name and side while its own doc comment claimed it validated, so a daemon could serve an illegal matchup for as long as it ran. It now runs `DeckFile::validate` — the same gate the CLI uses, so "playable" means one thing in both — and `check_rotating_pool` gives the rotating pool the same treatment at bind, which matters more: a pinned deck is refused by name, where a rotating one would have been dealt on whichever seed reached it. `ServeOptions::format` and `netrunner_server --format` default to Startup, matching the CLI.
- **Banlists and rotation — mechanism present, data still a seed, and that is now a recorded decision rather than a gap.** `banned` and `allowed_packs` are enforced; both tables are empty or scoped to the two embedded packs. Real lists cannot be sourced from inside `netrunner_core`, which has no I/O, and inventing entries would be worse than an empty table — an empty one is visibly a seed and a wrong one is not. So the paths are tested through `validate_deck_with_rules`, a seam that takes caller-supplied rules for exactly this reason, and `no_shipped_format_restricts_anything_yet` pins the current emptiness so filling it in is deliberate. **No shipped format rejects any shipped deck**: every published decklist is `sg`/`elev`, which is Startup's whole pool, verified across all four formats by `every_shipped_format_can_actually_serve_the_sample_pool` so the new daemon gate cannot become a startup failure.

Rotation by *cycle* was considered and dropped: `PackInfo` discards the `cycle_code` its DTO carries, and adding the structure buys nothing while the pool is two packs and the rotation data is unavailable. Revisit when a real feed exists — `netrunner_card_sync` is the crate that would fetch it.

## Phase 1.5 — Session Unification — DONE

Five copies of `current_actor` → action → `apply_action` → `GameOver`, each with its own budget, became **one `MAX_STEPS` in `netrunner_session`**. `Seat::Agent` | `Seat::External`; `PlayerDriver` deleted (a clone of `netrunner_bots::Agent`); the pull-shaped `step() -> SessionStep` collapses local-human, channel and indexed seats into one — **do not re-split**. `MatchHistory` moved into the driver (which gave the network path a log); `GameEndReason`/`classify_end_reason` moved to `netrunner_session::outcome`. The gym's budget is one `MAX_STEPS` per episode (it was 1,000 per fast-forward call, reset each call). `StallReason` splits `NoCurrentActor` / `NoLegalActions` / `BudgetExhausted` — and, since 5 September 2026, `DecisionLivelock` (Phase 2 §5).

**"A run can outlive the game" — a crash and a deadlock, both fixed.** `apply_damage` set `GameOver` without clearing `active_run`: `open_window` hit `unreachable!()` from inside `build_client_view` (rendering the position crashed the process), and `resolve_encounter_ice` left subroutines `Pending` so the priority holder's own `PassPriority` was illegal — no legal action, at `matchups()[0]` seed 2. Both invisible to the index-path sweeps; hence `no_deadlock_sweep.rs` drives view-based seats (AGENTS.md Testing Rule). The adjacent hazard — `Sequence` kept resolving after `GameOver` — was closed by the Rules Audit §4's `win::end_game` and `resolution_halted()`.
