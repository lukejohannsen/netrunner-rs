## 2. Rating & Elo Engine — DONE

`netrunner_rating` (`feat/rating-and-bench`): Glicko-2 (Glickman 2013; reproduces the paper's worked example), a `RatingBook` of one `Standing` (a Corp and a Runner `RoleRecord`) per `Track { HumanVsHuman, HumanVsBot, BotBenchmark }` per participant, one sorted JSON file. Glicko-2 over Elo because every consumer has few games and a deviation lets a ladder say `1612 ± 120` honestly. **A rating period of one game**, both updates from pre-game standings so order cannot matter and a bot may play itself. Tracks and roles never mix; `overall()` sorts a ladder only. Persistence belongs to the consumer (`bench --ratings`, the daemon's `--ratings-file`). **A forfeit is a loss**; a stall is unrated. **The idle seat is read too** (`fix/idle-seat-surrender`): `await_seat`'s third `select!` arm takes a `Surrender` at once and checks an out-of-turn `SubmitAction` against that seat's own `legal_actions_for` — the one place the host re-derives legality, because a `PlayerAction` carries no submitter (the first version applied the idle Runner's `KeepHand` as the Corp's mulligan). The grace clock moved onto the session so an applied idle action cannot restart it. Not built: telling the client its new rating; rating decay.
